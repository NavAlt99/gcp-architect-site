Support, Governance Basics, and Asset Inventory

1 Real-World Explanation

The Situation: Governance at Scale

Managing 5 projects is simple; managing 500 projects across 3,000 developers requires automated governance. Cloud Asset Inventory gives architects a real-time, searchable database of every virtual machine, bucket, IAM binding, and network rule across the entire Google Cloud organization. [1] [2]

Foundation references: Google Cloud documentation · Google Cloud Architecture Framework

The Pain

Support, Governance Basics, and Asset Inventory becomes risky when teams treat Support plans (Basic, Standard, Enhanced, Premium) as a checkbox instead of a boundary with an owner, evidence, and recovery path. [1] [2]

The Idea in One Paragraph

Support, Governance Basics, and Asset Inventory is a design decision anchored by Support plans (Basic, Standard, Enhanced, Premium). Connect it to Cloud Asset Inventory, make the dependency visible, and state what changes when the requirement or failure domain changes. [1] [2]

2 Technical Discussion & Architecture Diagrams

Layer 1 — Foundation: Google Cloud Support Tiers

  • Basic: Billing support and documentation only (Free). [1] [2]
  • Standard: 4-hour response time for P2 business issues ($29/mo + 3% spend). [1] [2]
  • Enhanced: 1-hour response time for P1 critical issues ($500/mo + 3% spend). [1] [2]
  • Premium: 15-minute response for P1 outages, designated Technical Account Manager (TAM), and Event Management ($12,500/mo + spend). [1] [2]

Layer 2 — Practitioner: Launch Stages (Preview vs GA)

Never run production workloads on Preview or Early Access features. Only Generally Available (GA) products carry Google Cloud SLAs and full enterprise support backing. [1] [2]

Layer 3 — Architect: Cloud Asset Inventory Queries

Use gcloud asset search-all-resources and search-all-iam-policies to audit compliance across thousands of projects in seconds. [1] [2]

Layer 4 — Staff: Personalized Service Health API

Do not rely on the public status dashboard. Integrate the Personalized Service Health API into PagerDuty to receive automated alerts for incidents specifically impacting your project IDs. [1] [2]

Technical references: Google Cloud documentation · Google Cloud Architecture Framework

Scope and planes

The scope of Support, Governance Basics, and Asset Inventory is set by Support plans (Basic, Standard, Enhanced, Premium). Separate the control-plane decision from the runtime path, and state which organization, project, region, zone, or resource owns the boundary. [1] [2]

Practitioner defaults and troubleshooting

Start by verifying Cloud Asset Inventory, then inspect the identity, quota, network, logging, and dependency evidence that can invalidate that assumption. [1] [2]
