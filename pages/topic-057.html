1 Real-World Explanation

The Load Balancer Selection Decision Tree

Google Cloud Load Balancing is uniquely different from other clouds: it is fully distributed, software-defined (powered by Maglev and Andromeda), and requires no pre-warming to handle massive sudden traffic spikes. [1]

2 Technical Discussion & Architecture Diagrams

Layer 1 — Foundation: Application (L7) vs Network (L4)

Use Application Load Balancers (L7) when you need to inspect HTTP headers, cookies, URL paths (e.g. /api/* vs /static/*), or integrate with Cloud Armor and Cloud CDN. Use Network Load Balancers (L4) for raw TCP/UDP. [1]

Layer 2 — Practitioner: Proxy vs Passthrough Mechanics

In a Proxy load balancer, Google terminates the client connection and opens a separate backend connection (backend sees Google's proxy IP unless reading X-Forwarded-For). In a Passthrough load balancer, packets pass unchanged directly to the VM (backend sees the real client IP directly in the IP header). [1] [2]

Layer 3 — Architect: Cross-Region Spillover

Global External ALBs track backend capacity (utilization or RPS). If the primary region in us-east1 reaches 100% capacity during a flash sale, excess requests are automatically spilled over to us-central1 without returning errors to users. [1] [2]

Layer 4 — Staff: Serverless NEGs & Hybrid Connectivity NEGs

Network Endpoint Groups (NEGs) allow load balancers to route directly to serverless backends (Cloud Run, App Engine), Kubernetes pod IPs (Standalone NEGs), or on-premises servers via Cloud Interconnect. [1] [2]

4 Practice Exercise

Revision Drill: Load Balancer Selection

Select the exact load balancer for each requirement:
1. Global gaming backend receiving UDP telemetry and requiring client source IP preservation.
2. An e-commerce website requiring Cloud Armor WAF and Cloud CDN edge caching.
3. Internal communication between private GKE microservices requiring path-based URL routing.
4. A global non-HTTP encrypted TCP database gateway terminating TLS at Google's edge.

Answers

  1. External Passthrough Network Load Balancer (handles UDP, preserves client IP).
  2. Global External Application Load Balancer (L7, Cloud Armor, Cloud CDN).
  3. Internal Application Load Balancer (private IP, L7 URL path routing).
  4. External Proxy Network Load Balancer (global Anycast TCP/SSL termination).
