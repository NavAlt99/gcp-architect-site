Virtual Private Cloud (VPC) Networking & Security

Global software-defined enterprise networking: Custom VPCs, regional subnets, routes, hierarchical firewall policies, Shared VPC host/service projects, and Private Google Access.

1 Real-World Explanation

The Situation: The Global Software-Defined Network

Google Cloud's Virtual Private Cloud (VPC) is fundamentally different from other cloud providers. In AWS or Azure, a VPC is bound to a single region. In Google Cloud, a VPC is a global resource. Subnets are regional, meaning a single VPC can span multiple regions worldwide, allowing instances in Frankfurt, Iowa, and Tokyo to communicate across Google's private global fiber network without traversing the public internet. [1] [2]

The Auto Mode vs Custom Mode Rule
Never use Auto Mode VPCs in production. Auto mode creates a pre-assigned /20 subnet in every single Google Cloud region, using up RFC 1918 space and creating massive subnet overlap risks when connecting to on-premises networks or establishing VPC Peering. Always choose Custom Mode VPCs with explicit, deliberate CIDR allocations.

2 Technical Discussion & Architecture Diagrams

Layer 1 — Foundation: Subnets & Secondary Ranges

Subnets are regional. In GCP, exactly 4 IP addresses are reserved per subnet: .0 (network), .1 (default gateway), .2 (reserved by Google), and .3 (reserved by Google). Secondary ranges are used to allocate IP blocks for GKE Pods and Services. [1] [2]

Layer 2 — Practitioner: Shared VPC (The Enterprise Standard)

The standard enterprise architecture pattern is Shared VPC. A central network team manages the network in a Host Project (subnets, routes, firewall rules, VPN/Interconnect), while application teams deploy workloads in separate Service Projects attached to the host project's subnets. [1] [2]

Layer 3 — Architect: Private Google Access & Private Service Connect (PSC)

Private VMs without external IPs can access Google APIs (Cloud Storage, BigQuery) securely via Private Google Access. To consume internal SaaS services or multi-tenant databases without VPC peering, use Private Service Connect (PSC) endpoints. [1] [2]

Layer 4 — Staff: Hierarchical Firewall Policies & Andromeda SDN

Staff architects use Hierarchical Firewall Policies attached at the Organization or Folder level to enforce non-negotiable security rules (e.g. deny all inbound port 22 except from IAP) across all projects in the company. [1] [2]

4 Hands-On Demo

Hands-On Demo: Building a Custom VPC with Private Subnets
# 1. Create custom VPC network
gcloud compute networks create production-vpc --subnet-mode=custom

# 2. Add regional subnets
gcloud compute networks subnets create us-west-web   --network=production-vpc   --region=us-west1   --range=10.10.1.0/24   --enable-private-ip-google-access

# 3. Create firewall rule allowing internal traffic
gcloud compute firewall-rules create allow-internal-vpc   --network=production-vpc   --allow=tcp,udp,icmp   --source-ranges=10.10.0.0/16
