1 Real-World Explanation

Case Profile: Mountkirk Games

Company Background: Mountkirk Games is an established mobile game studio expanding into real-time, global multiplayer gaming. Their previous game experienced unexpected viral popularity, which overwhelmed their legacy single-region MySQL database and caused hours of game downtime. [1] [2]

Mountkirk Games Requirements Breakdown
  • Business Goals: Deliver a seamless, lag-free global player experience; scale instantly during marketing campaigns; minimize operational management; monetize game data with machine learning. [1] [2]
  • Technical Requirements: Global low-latency data access; relational consistency for in-game purchases and currency balances; 99.999% database availability; ingestion of 500,000 score events/sec. [1] [2]
  • Watchpoints: Single-region databases cannot support global writes without cross-region replication lag; manual server provisioning cannot keep pace with viral spikes. [1] [2]

2 Technical Discussion & Architecture Diagrams

Layer 1 — Foundation: Global Anycast Routing (Global External ALB)

Use a single Anycast IP address to terminate client connections at the nearest Google edge PoP, routing traffic across Google's private fiber backbone to regional GKE clusters. [1] [2]

Layer 2 — Practitioner: GKE Autopilot for Game Server Fleets

Run game server containers on GKE Autopilot. Autopilot automates node provisioning, OS patching, and cluster hardening, eliminating operational toil so game developers can focus on gameplay mechanics. [1] [2]

Layer 3 — Architect: Cloud Spanner Multi-Region for In-Game Purchases

Deploy Cloud Spanner in a multi-region configuration. Spanner provides relational ACID guarantees, 99.999% SLA availability, and synchronous Paxos replication, ensuring in-game coin balances are never corrupted or double-spent. [1] [2]

Layer 4 — Staff: Streaming Telemetry Pipeline (Pub/Sub > Dataflow > BigQuery)

Stream real-time game telemetry through Cloud Pub/Sub into Dataflow (running Apache Beam windowing) and sink directly into BigQuery for real-time fraud detection and churn modeling. [1] [2]

4 Practice Exercise

Practice Exercise: Mountkirk Database Selection Justification

An exam scenario asks: "Mountkirk Games needs a transactional database to store user currency balances. The game is played simultaneously across North America, Europe, and Asia. Players must never experience stale currency balances or double-spending, and the database must guarantee 99.999% availability. Which database must be chosen?"

Justify why Cloud Spanner is the only correct answer.

Defended Justification

Cloud Spanner Multi-Region is the only database in Google Cloud that provides: (1) Globally distributed synchronous relational ACID transactions, (2) Strong external consistency using TrueTime atomic clocks, and (3) A 99.999% SLA (less than 5.26 minutes of downtime per year). Cloud SQL only reaches 99.95% within a single region, Bigtable lacks multi-row ACID transactions, and Firestore does not provide 99.999% multi-region relational SQL.
