1 Real-World Explanation

Case Profile: Helicopter Racing League (HRL)

Company Background: The Helicopter Racing League (HRL) is a global sports organization that organizes high-speed helicopter races in diverse locations worldwide. They want to modernize their broadcast platform to deliver ultra-low latency video streaming, real-time telemetry overlays, and predictive race analytics. [1] [2]

HRL Requirements Breakdown
  • Business Goals: Increase fan engagement with immersive digital broadcasts; expand viewer base globally; provide real-time predictive telemetry overlays (e.g. probability of pilot overtaking in turn 3). [1] [2]
  • Technical Requirements: Transcode high-definition live video feeds into multi-bitrate streams with sub-3 second latency; ingest high-frequency telemetry from racing helicopters; support millions of concurrent global viewers. [1] [2]
  • Key Challenge: Balancing compute-intensive video encoding with low-latency edge caching and real-time machine learning predictions. [1] [2]

2 Technical Discussion & Architecture Diagrams

Layer 1 — Foundation: Video Ingestion & Transcoder API

Use the Live Stream API and Transcoder API to convert raw RTMP/SRT video feeds into multi-bitrate HTTP Live Streaming (HLS) and Dynamic Adaptive Streaming over HTTP (DASH) segments. [1] [2]

Layer 2 — Practitioner: Media CDN & Cloud CDN Edge Delivery

Deliver video segments via Media CDN (built on Google's YouTube infrastructure). Media CDN provides edge caching at hundreds of metropolitan locations, offloading origin servers and eliminating stream buffering. [1] [2]

Layer 3 — Architect: Real-Time Telemetry Pipeline (Pub/Sub & Dataflow)

In-flight telemetry (speed, G-force, altitude, engine RPM) streams through Cloud Pub/Sub into Dataflow. Telemetry is joined with live video timestamp metadata to synchronize graphic overlays. [1] [2]

Layer 4 — Staff: Vertex AI Real-Time Prediction Overlays

Deploy trained TensorFlow models to Vertex AI Endpoints. The model evaluates current flight trajectories and outputs probability scores for live broadcast overlays with sub-100ms inference latency. [1] [2]

4 Practice Exercise

Practice Exercise: Live Video Streaming Architecture Defense

An exam scenario asks: "HRL needs to deliver live race video streams to millions of concurrent viewers globally with minimum latency and highest cache hit ratio, while preventing origin server exhaustion. Which edge service should be deployed?"

Contrast Cloud CDN / Media CDN with self-hosting NGINX reverse proxies on Compute Engine.

Defended Answer

Cloud CDN / Media CDN leverages Google's global edge network of thousands of Points of Presence (PoPs) connected via private fiber. It automatically caches video chunks (HLS/DASH) at the edge closest to the user, providing over 95% origin cache offload with sub-second latency. Self-hosting NGINX proxies on Compute Engine requires manual autoscaling, cannot match Google's global Anycast edge presence, and introduces severe single-region origin bottlenecks under viral viewer spikes.
