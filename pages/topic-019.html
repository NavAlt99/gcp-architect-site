Cloud Storage, Object Lifecycle, and Enterprise File Systems

Planetary-scale unstructured storage: Cloud Storage classes (Standard, Nearline, Coldline, Archive), Autoclass, retention policies, Bucket Lock, and managed Filestore NFS.

1 Real-World Explanation

The Situation: The Universal Object Store

Cloud Storage (GCS) is Google Cloud's foundational service for unstructured object data (media files, analytics data lakes, database backups, website assets). Every object is stored with 99.999999999% (11 9s) annual durability through automated erasure coding across independent physical failure domains. [1] [2]

Storage Classes: Balancing Access Frequency and Cost
  • Standard: Active, frequently accessed data (websites, mobile apps, streaming media). No retrieval fees, no minimum storage duration. [1] [2]
  • Nearline: Accessed less than once a month (monthly backups, recent reports). Low storage cost, small retrieval fee, 30-day minimum duration. [1] [2]
  • Coldline: Accessed less than once a quarter (disaster recovery data). Ultra-low storage cost, 90-day minimum duration. [1] [2]
  • Archive: Accessed less than once a year (regulatory compliance, tax archives). Lowest storage cost, 365-day minimum duration. [1] [2]
  • Autoclass: Automatically transitions objects between classes based on access patterns without manual lifecycle rules. [1] [2]

2 Technical Discussion & Architecture Diagrams

Layer 1 — Foundation: Location Types & Replication

  • Regional: Stored within one region across 3 zones. Lowest cost; highest in-region compute performance. [1] [2]
  • Dual-Region: Stored across two specific regions (e.g. nam4: Iowa and South Carolina) with Turbo Replication for 15-minute RPO failover. [1] [2]
  • Multi-Region: Geo-redundant storage spread across a continent (e.g. US or EU). Survives full regional catastrophe. [1] [2]

Layer 2 — Practitioner: Uniform Bucket-Level Access (UBLA)

Always enable Uniform Bucket-Level Access. UBLA disables legacy per-object Access Control Lists (ACLs) and unifies all security under Cloud IAM. This prevents accidental data leaks caused by legacy object permissions. [1] [2]

Layer 3 — Architect: Signed URLs & Direct Client Uploads

Never proxy large file uploads through backend API servers. Have the server generate a cryptographic Signed URL with a 15-minute expiration, allowing the user's browser to stream gigabytes directly into Cloud Storage. [1] [2]

Layer 4 — Staff: Bucket Lock (WORM Compliance)

For regulatory compliance (SEC Rule 17a-4, FINRA, HIPAA), architects configure Retention Policies with Bucket Lock. Once locked, objects cannot be deleted or overwritten by any user (including Google support) until the retention duration expires. [1] [2]
