1 Real-World Explanation

The Situation: High-Velocity, Low-Risk Delivery

High-performing organizations do not choose between speed and stability. Research from DORA (DevOps Research and Assessment) proves that elite engineering teams deploy code multiple times per day while maintaining drastically lower failure rates. [1] [2]

Google Cloud provides an integrated serverless continuous integration and continuous delivery (CI/CD) ecosystem: [1] [2]

The Four Core DORA Metrics
  • Deployment Frequency: How often code is successfully deployed to production (Elite: multiple deploys per day). [1] [2]
  • Lead Time for Changes: Time from code commit to running in production (Elite: less than one hour). [1] [2]
  • Mean Time to Recovery (MTTR): How long it takes to restore service after an incident (Elite: less than one hour). [1] [2]
  • Change Failure Rate: Percentage of deployments that cause a production failure or rollback (Elite: 0-15%). [1] [2]

2 Technical Discussion & Architecture Diagrams

Layer 1 — Foundation: Cloud Build Serverless Pipelines

Cloud Build executes builds on fully managed, serverless infrastructure scaling to hundreds of concurrent workers. Define builds in cloudbuild.yaml with parallel build steps, caching, and substitutions. [1] [2]

Layer 2 — Practitioner: Modern Artifact Registry Practices

Never overwrite the latest tag. Tag images with immutable Git commit SHA hashes (e.g., us-central1-docker.pkg.dev/proj/repo/app:sha-a8f23c). Enable automated vulnerability scanning and cleanup policies. [1] [2]

Layer 3 — Architect: Cloud Deploy & Progressive Canary Promotion

Cloud Deploy separates CI from CD. It manages delivery pipelines across target stages (Dev > Staging > Prod). Supports automated Canary deployments: deploy 10% to production, pause for approval or verification, then promote to 100%. [1] [2]

Layer 4 — Staff: Secure Supply Chain Pipelines (SLSA 3)

Staff architects enforce private worker pools with zero public IPs, service account token impersonation, and automated Binary Authorization signing at the build stage. [1] [2]

Technical references: Cloud Build documentation · Cloud Deploy documentation

4 Hands-On Demo

Hands-On Demo: Creating a Cloud Deploy Delivery Pipeline

Define a declarative continuous delivery pipeline promoting releases from staging to production.

# clouddeploy.yaml
apiVersion: deploy.cloud.google.com/v1
kind: DeliveryPipeline
metadata:
  name: order-service-pipeline
description: Production delivery pipeline for Order Microservice
serialPipeline:
  stages:
  - targetId: staging-cluster
    profiles: [staging]
  - targetId: prod-cluster
    profiles: [prod]
    strategy:
      canary:
        runtimeConfig:
          kubernetes:
            serviceNetworking:
              service: "order-service"
              deployment: "order-service"
        canaryDeployment:
          percentages: [25, 50]
          verify: true
