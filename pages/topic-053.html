Data Lake, Lakehouse & BigLake: Open Table Formats & Governance

Architecting the enterprise lakehouse: Cloud Storage tiered storage zones (raw, curated, consumption), open formats (Parquet, ORC, Iceberg), BigLake storage abstraction, and Dataplex unified data governance.

1 Real-World Explanation

The Situation: From Data Swamp to Modern Lakehouse

Organizations often start their big data journey by dumping every file, log, and database export into an unorganized Cloud Storage bucket. Without governance, this quickly degenerates into an unsearchable "Data Swamp"—full of stale, duplicate, uncataloged files with zero access control. [1] [2]

The Data Lakehouse pattern combines the low cost, flexibility, and open formats of a Cloud Storage Data Lake with the ACID transactions, data governance, and high performance of a Data Warehouse. [1] [2]

The Three Standard Storage Zones
  • Raw Zone (Bronze): Immutable, raw source data preserved in its original format (JSON, CSV, raw binary). Used for forensic re-processing. [1] [2]
  • Curated / Cleaned Zone (Silver): De-duplicated, schema-validated data converted into high-performance columnar formats (Parquet, ORC, Apache Iceberg). [1] [2]
  • Consumption / Analytics Zone (Gold): Aggregated, business-ready data models and data marts ready for executive Looker dashboards and machine learning feature stores. [1] [2]

2 Technical Discussion & Architecture Diagrams

Layer 1 — Foundation: Open File Formats (Parquet vs CSV/JSON)

Never query raw CSV or JSON in production analytics. Apache Parquet is a columnar format with built-in compression (Snappy) and column statistics (min/max), allowing query engines to skip irrelevant byte ranges. [1] [2]

Layer 2 — Practitioner: Open Table Formats (Apache Iceberg)

Traditional data lakes suffer from lack of ACID transactions (writing files during concurrent reads causes partial reads). Apache Iceberg brings ACID transactions, time travel (querying historical snapshots), and schema evolution to Cloud Storage files. [1] [2]

Layer 3 — Architect: BigLake Storage Engine

BigLake unifies data warehouses and lakes. It extends BigQuery's storage engine to external Cloud Storage buckets, enforcing column-level and row-level access control regardless of whether the query originates from BigQuery, Spark, or TensorFlow. [1] [2]

Layer 4 — Staff: Dataplex Unified Data Mesh Governance

Staff architects implement Dataplex to manage data mesh architectures. Dataplex logically organizes decentralized data across multiple GCP projects into centralized "Lakes" and "Zones" with automated data quality checks and lineage tracking. [1] [2]

Technical references: BigLake documentation · Dataplex Universal Catalog
